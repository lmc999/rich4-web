# 有意偏差清单（DEVIATIONS）

> 来源：`docs/architecture.md` §7.3（初始内容），细节见各领域设计。规则基准是原版程序的实际行为（v3.11 逆向为主、v2.06 核实）；下表列出**有意**与原版不同的地方。
> 每条要么有开关（房间设置 / `RuleConfig` / 构建变量），要么写明理由。凡因 `docs/VERIFY.md` 的核实结论而新增、修改或撤销的条目，按 architecture.md §11 末尾的回写路径同步：先改数据表或 `RuleConfig` 默认值，再刷新 golden，升 `ENGINE_VERSION` 的次版本号，最后更新本文件与 VERIFY.md。

| 编号 | 偏差 | 原版行为 | 我们的做法 | 开关或理由 |
|---|---|---|---|---|
| DEV-01 | 金额、点券溢出默认饱和 | 金额按 int32 回绕，点券按 uint16 回绕（`&0xffff`），长局可能出现负资产或点券清零 | `RuleConfig.intOverflow` 默认 `'saturate'`：金额夹在 ±2147483647，点券夹在 0..65535；数值计算仍按 int32 语义（`add32`、`Math.imul`、`divTrunc`）。`'wrap'` 下报价（过路费、买地、加盖）可能回绕成负数，资金原语按 C 语义照常执行：付款时钱反向流动（付款方第一个口袋增加、收款方减少），只有「现金 + 存款 < 金额」才破产；只用现金的消费以「价格 ≤ 现金」为准，负价时现金反增。⚑ 原版对负金额的处理没有指令级证据，按 C 的比较与减法推定 | 开关 `intOverflow: 'wrap'` 恢复原版回绕。理由：溢出是实现缺陷而非规则，联机长局里负资产会破坏物价指数与胜负判定（design/engine.md §3、design/minigames-ai.md §0） |
| DEV-02 | 引擎 RNG 改用 xoshiro128** | 全局 Watcom C `rand()`（15 位 LCG），公式写成 `rand()%n` | 引擎用可序列化的 xoshiro128**，对外提供 `rand15()`（0..32767），公式保留 `rand15()%n`，因此取值分布相同；每次取数带 purpose 标签，测试可按语义强制结果。小游戏 sim 与 AI 用 `util/rng/watcom.ts`，分布与原版一致 | 无开关。理由：服务器权威模式不需要与原版随机序列逐位对拍（原版序列本来也无从对拍）；xoshiro 质量更好，可序列化进 `state.secret.rng`，便于存档、重放与场景测试（design/engine.md §0、§2） |
| DEV-03 | AI 随机数按决策派生、稳定排序、固定视角 0 | 电脑与游戏共享同一条全局 `rand()` 序列；候选排序用不稳定的 `qsort`；AI 的「视野」随当时的镜头视角档位变化 | 种子按 `(aiSeed, seat, decisionId \| turnIndex+salt)` 派生（`aiSeed` 在 `secret` 中，只有 AiDriver 可读）；同分候选按下标或 id 稳定排序；视野固定使用规范视角 0 | 无开关。理由：联机时各客户端视角不同，AI 行为必须与观察者无关；决策级派生让同一局可复现、AI 不影响引擎 RNG 序列（design/minigames-ai.md §8–9） |
| DEV-04 | 目标范围与 AI 视野用世界坐标方窗近似 | 以角色为中心的 440×440 **屏幕**视窗（经等角投影），判定 −220 ≤ 投影偏移 < 220 | v1 由 `shared/geom/viewWindow.ts` 统一实现：世界坐标方窗，半宽 220，半开区间；引擎算目标候选与 AI 判视野共用这一个函数 | 开关 `RuleConfig.targetRange`：`'window'`（默认，`windowHalf` 220）或 `'global'`（全图）。V-E10 取得原版视角 0 投影表后换成投影版，并升 `ENGINE_VERSION` 次版本号 |
| DEV-05 | 时光机的联机语义 | 单机：全场一个锚点，取最近一次真人掷骰前的世界；使用后恢复整个世界，随机数作为延续点继续 | 锚点 = 真人座位提交 ROLL 前的世界（公开世界 + 帧栈 + 新闻命运的牌序与游标，不含 rng、counters）；回滚时 RNG 与决策 id 都不回退，恢复后的世界里使用者的时光机 −1（最低 0）并刷新锚点；座位的 controller / aiTraits（服务器写入的踢人、认领、托管设置）与 config 不回滚；`perSeat` 下其他座位在恢复点之后的锚点作废、之前的锚点里使用者的时光机同样 −1；导入存档时锚点世界与 GameState 同样校验结构与不变量；发 `TIME_REWOUND`，同一批末尾补 `SYNC{reason:'timeRewind'}`，客户端整体 reset；AI 永不使用。M7 已实现（architecture §21.1），回合菜单的目标面板提示要回到的回合 | 开关 `RuleConfig.timeMachine`：`'global'`（默认，原版）、`'perSeat'`、`'disabled'`。多真人房间 UI 提示它会回滚他人的操作并推荐 disabled；最终默认值待用户拍板（design/engine.md §10.10） |
| DEV-06 | 真人可在小游戏倒计时阶段主动跳过 | 只有全局设定「動畫過程」关闭时，真人才走不玩分支（50 + rand%20 点券）；否则必须亲自玩 | 开局前 3 秒倒计时内可点「跳过」，走与原版不玩分支完全相同的结算（`score = 50 + rand15()%20`，`speechSlot = rand15()&1`，恰好 2 次取数）；开局后再发 decline 被拒 | 房间设置 `allowMinigameDecline`（默认 true）。理由：相当于把原版全局开关细化到每位玩家，结果仍在原版可达范围内（design/minigames-ai.md §2） |
| DEV-07 | 企鹅用几何菱形拾取；气球点击按最近 tick 归属 | 企鹅按 Panel#81 逐像素命中表判定；气球点击在当前帧生效 | 企鹅：`\|dx\|*24 + \|dy\|*48 ≤ 48*24` 的菱形判定，边缘最多差一两个像素；气球：插值系数 α < 0.5 时把点击记到 t−1，客户端本地回滚一步重算 | 无开关。理由：美术自制，不读取原版命中表；插值渲染会让画面落后于逻辑位置，按最近 tick 归属后偏差 ≤ 24px，小于最小命中框半高 26px，且不影响确定性（design/minigames-ai.md §3.3、§2.2、§7.2） |
| DEV-08 | 神明重生尝试 64 次后放宽距离约束 | 从可走、无禁放、无人、无物件的路面格中随机抽，X 或 Y 方向与参照点相距 ≥300 才接受，否则一直重抽 | 最多尝试 64 次，仍不满足就改为任意合法节点；乞丐被施舍后换位沿用同一规则（原版乞丐换位的候选为 0 时会除零崩溃） | 无开关。理由：保证在小地图（fixture）或极端占位下必然终止，不出现死循环；台湾图上几乎不会触发（design/engine.md §10；architecture §20.2） |
| DEV-09 | 单次超时默认执行 defaultIntent | 单机无超时概念，玩家可以无限思考 | 决策超时后执行该决策的 `defaultIntent`（不买、不用卡、掷骰……），不交给 AI 代决；连续 2 次超时进入托管（AI 代打） | 房间设置 `timeoutPolicy`：`'default'`（默认）或 `'ai'`（超时由 AI 代决）。理由：偶发超时保守处理，避免 AI 替真人做出激进决定（architecture.md §14 net） |
| DEV-10 | 美术、音频全部自制；角色名走 i18n | 原版位图、FLIC 动画、MIDI 与语音 | 程序化 SVG/Pixi 绘制与自制或许可明确的音频；沿用原作 12 个角色名，文案全部走 i18n | 构建变量 `VITE_NAMESET=alt` 一键替换为 `characters.alt.json`。理由：不分发任何原版素材（用户决策 0.5） |
| DEV-11 | AI 不使用特別融資，不做公布栏重新定价 | 电脑可能使用特別融資（0x436b0a）；公布栏有「1/3 重新定价」分支（0x428a37 以后） | v1 的 AI 两者都不做 | 无开关。理由：这两块逆向尚未解明（design/minigames-ai.md §11 A12），待 V-C2 核实后再补 |
| DEV-12 | 证据缺失的规则先按标注默认值实现 | 以原版程序实际行为为准，但部分行为尚无指令级证据 | 在代码和数据中标 ⚑，先按标注的默认值实现；可切换的做成 `RuleConfig` 开关或数据表字段（PROGRAM / MANUAL 预设见 architecture.md §7.1） | 逐项等待 `docs/VERIFY.md` 核实；结论出来后按本文件开头的回写路径更新 |
| DEV-13 | ⚑ 住旅馆 1 天也受阻 1 个回合 | 旅馆转盘转出 n 天时写阻碍计数 n − 1；n = 1 时写 0，等于完全不受阻（住 1 天没有效果） | n = 1 时写 0x80（下一回合走回棋盘、不掷骰），让「住 n 天」统一等于失去 n 个回合；航空出国 n 天仍写 n（n 个受阻回合 + 1 个走回的回合，与坐牢一致） | 无开关。理由：原版 n−1 的写法使 1 天档没有效果，推定为实现瑕疵；证据不足，以 VERIFY V-R20 实机结论为准（architecture §18.1） |
| DEV-14 | 百货公司每次进店最多 60 笔交易 | 一次进店可以无限买卖 | 引擎每笔交易后重发 SHOP，`SHOP_TRADE_LIMIT = 60` 笔后只能离开 | 无开关。理由：联机时防止刷交易拖住对局；正常游戏远达不到 60 笔（design/engine.md §8 kind 15） |
| DEV-15 | 农历覆盖到 2100 年 | exe 内置农历表只有 1998-01-01..2020-12-31，之后查表越界 | `data/calendar/lunar.ts` 用通行农历年信息表（1997..2100）；1998..2020 与 exe 逐日数据完全一致（测试对照 `.cache/extract` 的 lunar.packed），2100-02-29 按 03-01 换算 | 无开关。理由：长局或调日期后农历节日仍能正确判定；原版范围内结果不变 |
| DEV-16 | 小游戏点券一律饱和累加 | 点券按 uint16 存放，小游戏得分累加超过 65535 时回绕（`&0xffff`） | 小游戏结算（玩过与不玩分支）的点券一律夹在 0..65535（`addU16 'saturate'`），**不跟随** `RuleConfig.intOverflow`（其余点券来源仍按 DEV-01 的开关） | 无开关。理由：小游戏得分由客户端输入重放决定，回绕会让「玩得越好点券越少」；联机下这种反直觉结果只会引起争议（architecture §20.3） |
| DEV-17 | 拍卖改为多人并发出价 | 单机：同一台电脑上的一个拍卖界面，按加价档 / PASS / 放弃出价（r_property §9.2；询问顺序未逐指令核实） | AUCTION 帧同时询问所有可出价者，各自独立计时（超时默认 PASS）；有人加价后同一帧其他人的待答作废（在途请求收到 `STALE_DECISION`），按新价重新询问；「这轮不加价」只保持到下一次有人加价，「退出」永久退出；每口最少 +100，出价档 0（起拍价，仅无人出价时）/100/500/1000/5000/10000 | 无开关。理由：联机时逐人轮流会让等待时间随人数线性增长；并发 + 作废重问保证任何时刻只有一个现价、结果与出价到达顺序一致（服务器按到达顺序串行处理）（architecture §21.1） |
| DEV-18 | ⚑ 银行挤兑（新闻 22）用全场一个按日倒数的计数 | exe 给每位在场玩家各写一份「停贷」计数 15，在各自回合开头两段式倒数（非 0 减 1，减到 0 写 0x80、本回合仍生效，下个回合清 0；g_arbitration §3.2），判定看当前行动者自己的计数 | `econ.bankRunDays = 15`，日推进（DAY 帧）时减 1，> 0 期间全场 ATM 只能存、柜台不放款。抽到新闻者之后的座位与原版逐回合一致；抽到新闻者本人及座位在他之前的人少生效最后 1 个回合 | 无开关。理由：改为每人一份计数要给 PlayerState 加字段（state 结构 v2 + 迁移，含时光机锚点）并改前端银行面板，收益只是边界 1 个回合；留待 V-R21 实机核实挤兑细节时一并处理（architecture §21.6） |
| DEV-19 | 原版皮肤：小游戏入场 READY GO（Panel#78）在开局前播完 | 记忆阶段（1 秒）之后同步播放入场 FLC，播放期间小游戏计时暂停（exe 0x41436f 在消息 0x405 里） | 小游戏 sim 由服务器时间驱动、不能暂停，所以入场 FLC 按服务器时间逐帧选帧、恰好在 startsAt 播完：本人的遮罩提前 FLC 时长（2280ms）显示，期间提供「不玩了」（MINIGAME_DECLINE，保留 DEV-06） | 无开关。理由：联机下所有客户端与服务器裁判必须共用同一时间轴（architecture §24.2） |
| DEV-20 | 程序化皮肤的企鹅记忆阶段只画土堆 | 记忆阶段（1 秒）按类型画出埋藏物露头（exe 0x413f39(1)，Panel#80 图 kind+3） | 原版皮肤按 exe 画出种类；程序化皮肤（冻结为回退）仍只画不分种类的土堆，两种皮肤给玩家的信息量不同 | 皮肤选择即开关。理由：程序化美术冻结（architecture §16）；如要统一，改 `minigames/penguin/view.ts` 的土堆为 `drawItem`（V-R18） |
| DEV-21 | 原版皮肤：持骰动作在收到掷骰结果后才播；游戏速度按演出节奏固定 | 按下 GO 立刻播持骰动作（抱骰 → 抛出，逐 tick 一帧），播完才掷骰、放骰子 FLC；持骰动作、FLC 帧间隔随 RICH4.CFG 的游戏速度三档变化（tick 120/80/40 ms，FLC 50/30/20 ms/帧，exe 0x46a9d0、0x4730ec），可在游戏中调整 | 服务器权威掷骰：GO 只提交 ROLL，DICE_ROLLED 回来后才播持骰动作（多了一个网络往返），之后与原版同序（动作 → FLC 第 30 帧与播完各「咚」→ 点数面停留 → 起步）；速度档不单独设置：original 节奏 = 原版默认速度 1，compact 节奏 = 速度 2（shared/view/pacing 的 `DICE_TIMING`），预算按最多 9 帧持骰估计 | 房间设置 `pacing`。理由：点数只能由服务器决定；截止时间按同一张预算表计算，客户端不能自行调速（original-skin.md §4.1「掷骰」） |
