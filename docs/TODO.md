## 监狱 / 医院获释位置按原版（2026-10-01 取证，2026-10-02 已完成）

用户反馈：进监狱或医院后，人物应出现在设施外的第一格。v2.06 取证（radare2）后按方案 A 实施（architecture §29，ENGINE_VERSION 0.5.0）：
获释（0x40d184）不换节点，留在关押格、来路 = 关押格，下一回合在全部未封邻格里随机选（0x40bc10）；台湾监狱 1、医院 23 两条支线
（25 格、含 3 个小游戏格）从此可达；四张图 golden 已刷新；VERIFY V-M7 的释放位置与方向已关闭。剩下的：

- 原版关押期间不画棋子（0x4082a5–0x4082c3）、获释时从景观走 1 步到关押格；我们仍在关押格上画关押姿态，获释后没有走出动画（DEV-29），改不改由用户决定。
- 关押格能否放物件、能否作跳伞落点（V-M7 ③）仍待核。
- ~~AI 的 `lookbehind` 在获释后来路 = 关押格时的起点~~（2026-10-03 已核，无差异）：v3.11 0x40b343 以来路格为起点、排除当前格逐格外推（0 个候选回落为被排除的那一格，1 个候选不取随机数）；
  原版获释后来路仍是 0，节点 0 是全 0 哨兵、没有邻接，第一格回落为当前格（关押格），之后从关押格出发、排除 0，即全部未封邻格。
  我们来路 = 节点 = 关押格时 `nodes = [关押格, 未封邻格…]`，格序与取随机数的时机都相同。
- ~~关押期间被魔法屋「转向」改过来路~~（2026-10-03 已核，无差异，不必改 release()）：在押的人不会被转向或传送——魔法屋效果 7 `skipConfined`
  （`data/tables/magic.ts`，`effects/magic` applyToTarget 先跳过计数非 0 的人；原版 v2.06 0x43152a `cmp dword [+0x32], 0` / `jne` 同样跳过），
  转向卡与传送机经 `actorsInRange` → `boardPlayers` 取目标，在押的人不在候选里；关押期间除调试 teleport 外没有任何路径写在押者的 `prevNode`。
  release() 里重写 prevNode 只对 0.4.0 旧快照起作用，而旧快照里这个值本来也已是关押格。回归：`cards.test.ts`「6 转向 / 11 传送机：在押的人不是候选」、`magic.test.ts` 效果 7。

  （调用方 v3.11 0x4212ad / 0x4213e0 / 0x42158f 都是 lookbehind(6)，拿 out[0..5] = 往回第 2–7 格与候选比对）；我们 `ai/view.ts lookbehind` 第一格是来路格本身（往回第 1–6 格）。
  只影响电脑放路障（阶段二）、地雷、定时炸弹的选格；改了会改变 AI 决策与四张图 golden，要不要改由用户决定。
